# Desktop Release

Lume desktop releases are distributed through GitHub Releases and installed in-app with the Tauri updater.

## Required Secrets And Variables

- `TAURI_SIGNING_PRIVATE_KEY`: private key generated by `bunx tauri signer generate`.
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`: password for the signing key, if one was set.
- `LUME_UPDATER_PUBLIC_KEY`: repository variable containing the matching public key.

The checked-in `tauri.conf.json` uses `__LUME_UPDATER_PUBLIC_KEY__` as a placeholder so local development builds do not need a real key. Release builds provide `LUME_UPDATER_PUBLIC_KEY` in GitHub Actions, and the desktop shell embeds it at Rust compile time.

## Release Flow

1. Update versions in root `package.json`, `apps/desktop/package.json`, and `apps/desktop/src-tauri/tauri.conf.json`.
2. Create and push a tag such as `v0.1.1`.
3. GitHub Actions builds macOS, Windows, and Linux bundles.
4. The release remains as a draft until artifacts and notes are reviewed.
5. Publish the draft release. The updater endpoint reads `latest.json` from the latest GitHub Release.

## Local Commands

- `bun run build:desktop`: build web, sidecar, shared packages, and the Tauri desktop bundle.
- `bun run package:desktop`: alias for the desktop packaging flow.
- `bun run release:desktop`: local release packaging entrypoint.
