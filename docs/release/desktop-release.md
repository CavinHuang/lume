# Desktop Release

Lume desktop releases are distributed through GitHub Releases and installed in-app with the Tauri updater.

## Required Secrets And Variables

- `TAURI_SIGNING_PRIVATE_KEY`: private key generated by `bunx tauri signer generate`.
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`: password for the signing key, if one was set.
- `RELEASE_TOKEN`: GitHub token used by the release workflow to create draft releases, upload assets, delete stale assets on reruns, verify remote assets, and publish.
- `LUME_UPDATER_PUBLIC_KEY`: repository variable containing the matching public key.

The checked-in `tauri.conf.json` uses `__LUME_UPDATER_PUBLIC_KEY__` as a placeholder so local development builds do not need a real key. Release builds provide `LUME_UPDATER_PUBLIC_KEY` in GitHub Actions, and the desktop shell embeds it at Rust compile time.

## Release Flow

1. Update versions in root `package.json`, `apps/desktop/package.json`, and `apps/desktop/src-tauri/tauri.conf.json`.
2. Create and push a tag such as `v0.1.1`.
3. GitHub Actions creates or reuses one draft release for the tag and clears stale assets before rebuilding.
4. GitHub Actions builds macOS ARM, macOS Intel, and Windows x64 bundles. Linux desktop bundles are not part of this release workflow.
5. Each platform job verifies package inputs, smokes the compiled sidecar, uploads to the shared draft release by release id, and verifies local bundle artifacts.
6. A final remote gate verifies release assets and `latest.json` updater coverage for all supported platforms.
7. The workflow publishes the draft automatically only after all gates pass. The updater endpoint reads `latest.json` from the latest GitHub Release.

## Local Commands

- `bun run build:desktop`: build web, sidecar, shared packages, and the Tauri desktop bundle.
- `bun run package:desktop`: alias for the desktop packaging flow.
- `bun run release:desktop`: local release packaging entrypoint.
- `TAURI_TARGET_TRIPLE=<target> bun scripts/verify-desktop-package-inputs.mjs`: verify package inputs before Tauri packaging.
- `TAURI_TARGET_TRIPLE=<target> bun scripts/smoke-compiled-sidecar.mjs`: run the compiled sidecar and call `healthcheck`.
- `TAURI_TARGET_TRIPLE=<target> bun scripts/verify-desktop-package-artifacts.mjs`: verify local Tauri bundle outputs after packaging.

## Bundled Sidecar

Release builds compile `apps/sidecar/src/index.ts` into a standalone Bun executable before Tauri packaging. The generated file is written to `apps/desktop/src-tauri/binaries/lume-sidecar-<target-triple>` and is ignored by git. Supported release targets are:

- `lume-sidecar-aarch64-apple-darwin`
- `lume-sidecar-x86_64-apple-darwin`
- `lume-sidecar-x86_64-pc-windows-msvc.exe`

The Tauri bundle lists `binaries/lume-sidecar` in `externalBin`; Tauri adds the target triple during packaging and copies the binary into the installed app. At runtime, release builds start the bundled binary directly and do not fall back to system `node`, system `bun`, JS bridge resources, source paths, or `LUME_SIDECAR_CMD`. Development builds still use the Bun source entrypoint so local iteration remains fast.
