# Lume 文件与工作区重构设计

- 日期：2026-04-11
- 范围：Agent 右侧文件面板的信息架构与任务完成后的文件沉淀交互
- 目标：重构 `当前任务文件 / 工作区共享文件 / 外部附加目录` 三层模型，使用户能稳定理解文件归属与提升路径

## 1. 背景

当前 `Lume` 的文件与工作区体验存在认知混乱：

- 用户难以理解“线程文件 / 工作区文件 / 附加目录”各自的语义
- 右侧面板承担了过多展示和操作职责，结构不稳定
- 文件上传、附加、沉淀到长期层的动作边界不清楚
- 任务完成后，用户缺少清晰的“哪些文件值得沉淀到工作区共享文件”的引导

本次设计的目标不是扩展更多文件功能，而是先把信息架构讲清楚，并让后续 UI 与数据流围绕同一套心智模型收敛。

## 2. 设计目标

### 2.1 用户目标

用户需要能一眼理解：

- 哪些文件只属于当前任务
- 哪些文件属于当前工作区，可在多个任务间复用
- 哪些目录只是临时附加进来作为上下文

用户还需要在任务完成后，低成本地把值得复用的产物提升到工作区共享文件，而不需要手动整理全部文件。

### 2.2 系统目标

- 保留三层文件模型，但降低认知成本
- 明确每个上传/附加动作的归属
- 避免自动跨层迁移带来的不可预期行为
- 将“结构展示”和“任务收尾建议”分离，减少右侧面板复杂度

## 3. 核心信息架构

系统固定采用以下三层模型：

### 3.1 当前任务文件

- 定义：当前线程/任务内部产生和消费的文件
- 语义：任务私有、短生命周期、默认不跨任务复用
- 用户心智：这次任务的产物

### 3.2 工作区共享文件

- 定义：当前 workspace 下可被多个任务复用的长期资料
- 语义：工作区级共享、稳定沉淀、需要显式管理
- 用户心智：以后别的任务也会继续用的资料

### 3.3 外部附加目录

- 定义：临时挂进来供当前任务读取或操作的外部目录
- 语义：任务级临时上下文，不属于 workspace 资产
- 用户心智：这次顺手借来用一下的目录

### 3.4 结构原则

- `当前任务文件` 与 `工作区共享文件` 是并列主层
- `外部附加目录` 不是第三个正式资产层，而是临时上下文层
- 系统内任何 UI、文案、上传行为都不能模糊这三者的区别

## 4. 右侧面板布局设计

右侧面板采用“三层语义、两主一区辅”的布局：

### 4.1 当前任务文件区

- 位于上半部分
- 展示说明：`本次任务专属产物，仅当前任务可见`
- 中间为独立滚动的文件区
- 底部固定上传区，用于向当前任务层写入文件/文件夹

### 4.2 工作区共享文件区

- 位于下半部分
- 展示说明：`当前工作区内多个任务可复用的长期资料`
- 中间为独立滚动的文件区
- 底部固定上传区，用于向工作区层写入文件/文件夹

### 4.3 外部附加目录区

- 不单独占据主区域
- 依附在 `当前任务文件` 区块中展示
- 文案必须强调其临时性：`临时挂载，不属于工作区资产`
- 默认可见，但视觉权重弱于两个主文件层

### 4.4 布局原则

- 两个主文件层都采用“标题栏 + 中间滚动区 + 底部固定上传区”
- 两主层之间用明确分隔线，而不是依赖颜色暗示层级
- 外部附加目录不与共享文件混排，避免被误解成长期资产

## 5. 上传与附加入口规则

### 5.1 当前任务文件区

该区块内的入口只做一件事：

- `添加文件`
- `添加文件夹`

其结果仅写入 `当前任务文件`。

### 5.2 工作区共享文件区

该区块内的入口只做一件事：

- `添加文件`
- `添加文件夹`

其结果仅写入 `工作区共享文件`。

### 5.3 外部附加目录

该动作不再被理解为“上传”：

- 操作名：`附加外部目录`
- 行为：只做临时挂载，不复制进任务层或共享层

### 5.4 交互约束

三个动作必须在 UI 语义上严格区分：

1. 写入当前任务层
2. 写入工作区共享层
3. 临时附加外部目录

不能再用模糊入口让用户猜测文件最终落点。

## 6. 任务完成后的推荐提升卡片

### 6.1 定位

推荐提升不是文件浏览行为，而是任务收尾行为。

因此它不应放进右侧面板，而应出现在消息流中，作为任务完成后的系统建议卡片。

### 6.2 触发条件

当满足以下任一条件时，系统可以生成推荐卡片：

- 当前任务完成
- 当前轮 Agent 明确产出新文件并结束

### 6.3 卡片内容

卡片展示：

- 标题：`这些文件可能值得沉淀到工作区共享文件`
- 说明：`当前任务文件默认仅属于本次任务。若后续任务还会继续使用，可以提升到工作区共享文件。`
- 候选文件列表
- 单个 `提升`
- `全部提升`
- `暂不处理`

### 6.4 交互位置

卡片应位于任务完成消息之后，作为任务收尾的一部分。

### 6.5 为什么不放右侧面板

- 右侧面板负责回答“文件现在在哪里”
- 推荐卡片负责回答“哪些文件应该进入长期层”
- 将推荐逻辑塞进面板会让面板再次变成复杂操作台

## 7. 提升后的数据流与状态规则

### 7.1 默认归属

- 新生成文件默认进入 `当前任务文件`
- 用户从哪个区块上传，就落到哪个区块
- 外部附加目录永远不改变归属，它只是挂载

### 7.2 提升规则

- 允许从 `当前任务文件` 提升到 `工作区共享文件`
- 默认执行“复制”，不是“移动”
- 提升后，任务层原文件保留
- 提升成功后，推荐卡片中的对应项变为 `已提升`

### 7.3 重名规则

若共享层已存在同名文件，系统不能静默覆盖。

用户必须显式选择：

- `覆盖共享文件`
- `另存为`
- `取消`

### 7.4 推荐卡片状态

- 未处理：`可提升`
- 已处理：`已提升`
- 用户选择 `暂不处理`：本轮卡片不再继续追问
- 但文件仍保留在任务层，之后可以手动提升

### 7.5 面板联动

提升成功后：

- `工作区共享文件` 区块立即刷新
- `当前任务文件` 区块保持不变
- 不允许因提升动作触发消息区或面板的大幅抖动

### 7.6 Agent 行为边界

- Agent 可以正常在任务层读写
- Agent 不应默认把产物直接写入共享层，除非用户明确要求
- 共享层代表“用户确认沉淀的长期资料”，不是 Agent 擅自归档的位置

## 8. 推荐方案

本次设计推荐采用以下组合：

- 右侧面板负责稳定展示三层文件结构
- 消息流负责展示任务完成后的“推荐提升”卡片
- 数据规则坚持“默认安全、显式沉淀、不自动跨层”

该组合可以同时满足：

- 三层模型清晰
- 面板职责稳定
- 用户在任务完成时有明确沉淀路径
- 不引入自动化跨层迁移的行为风险

## 9. 非目标

本次设计不覆盖以下事项：

- 自动将任务文件迁移到共享层
- 将外部附加目录持久化为工作区长期资产
- 对 Chat 模式单独建立另一套文件层模型
- 扩展与本次信息架构无关的文件能力

## 10. 成功标准

若该设计实施完成，应满足：

- 用户能用一句话区分三层文件语义
- 用户上传文件时不再困惑文件最终归属
- 任务完成后，系统可以明确建议哪些文件值得沉淀
- 面板只负责结构展示，不承担任务收尾推荐逻辑
- 任务层与共享层不会因默认行为不断混杂

## 11. 实施收尾要求

在实现计划的最后，必须追加一项收尾任务：

- 创建一个 `Lume` 自我进化用的 skill
- 将本次文件管理设计中的核心理念写入该 skill

该 skill 至少需要覆盖以下原则：

- `当前任务文件 / 工作区共享文件 / 外部附加目录` 三层模型
- 当前任务层与工作区层的并列关系
- 外部附加目录的临时上下文语义
- 文件默认归属与“显式提升”规则
- 任务完成后推荐沉淀到工作区共享文件的理念

该项要求的目标不是增加一个无关附属物，而是把文件管理理念沉淀为 `Lume` 后续可持续自我修正、自我演化时能反复复用的系统性知识。
