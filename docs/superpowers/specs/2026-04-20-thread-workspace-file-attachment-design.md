# 线程与工作区文件附加区重设计

> 日期: 2026-04-20  
> 状态: 已批准（对话确认）  
> 分支: feat/new-ui

## 概述

重新设计 Agent 右侧文件面板中的线程文件与工作区共享文件区域，保留现有双 tab 结构，但把底部上传区升级为更明确的“文件附加区域”，并补足文件夹附加、工作区复用、以及外部附加来源可追溯能力。

这次设计的核心不是把文件浏览器改成全新的资源中心，而是在保留现有文件树心智的前提下，让“往当前线程或工作区里加文件 / 文件夹”这件事变得更直接、更不绕，并让用户能识别哪些资源来自外部附加。

## 背景与问题

当前实现已经支持：

- `当前线程文件` tab 中浏览线程目录
- `工作区共享文件` tab 中浏览工作区 `resources` 目录
- 底部拖拽上传区向线程附加文件

但这套交互仍有几个明显问题：

1. **底部区域语义偏“上传器”**  
   现在的 `FileDropZone` 更像技术实现层的上传入口，而不是用户能一眼理解的“附加到哪里”。

2. **附加路径不够直接**  
   用户最关心的是“把这个文件或文件夹放到当前线程 / 工作区”，但界面没有把归属范围表达清楚。

3. **文件夹附加心智不明确**  
   当前文案主要围绕文件，用户难以确认文件夹是否是同等支持的一类资源。

4. **工作区共享缺少快速复用动作**  
   工作区资源能浏览，但缺少清晰的“附加到当前线程”路径，导致共享资源复用不顺手。

5. **外部附加来源不可追溯**  
   一旦文件进入线程或工作区列表，就难以区分它是用户从本地附加进来的，还是 Agent 运行过程中产生的。

## 设计目标

### 主要目标

1. 保留两个 tab，不改变线程与工作区的现有空间模型
2. 让两个 tab 都能直接附加文件和文件夹
3. 让底部入口明确表达附加目标范围
4. 让工作区资源可以快速附加到当前线程
5. 仅对“外部附加”资源做轻量标识，并支持追溯原始绝对路径

### 非目标

- 不取消双 tab 改成统一大面板
- 不把列表区改造成独立的资源数据库视图
- 不给 Agent 产出项目增加来源标识
- 不在列表中常驻展示绝对路径
- 不新增复杂筛选、排序、批量操作能力

## 信息架构

### 保留双 tab

文件侧栏仍然保留两个 tab：

1. `当前线程文件`
2. `工作区共享文件`

两者继续使用文件树视图作为主体，但不再只是“浏览两个目录”：

- `当前线程文件`：展示当前线程目录中的文件与文件夹，并支持向当前线程附加外部文件或文件夹
- `工作区共享文件`：展示工作区共享目录中的文件与文件夹，并支持向工作区附加外部文件或文件夹，以及把共享资源继续附加到当前线程

### 底部固定附加区域

底部固定区域从“拖拽上传区”重定义为“文件附加区域”。

它在两个 tab 中都存在，但文案和行为随 tab 切换：

- 当前线程 tab：`附加到当前线程`
- 工作区共享 tab：`附加到工作区`

## 详细设计

### 一、底部文件附加区域

#### 交互形式

采用统一的 `拖拽卡片区 + 两个主按钮`：

- `附加文件`
- `附加文件夹`

拖拽继续保留，但作为辅助方式，不再是主心智入口。

#### 当前线程 tab 下的表现

- 标题：`附加到当前线程`
- 说明：`这些文件或文件夹会成为当前线程可用的上下文资源`
- 拖拽文案：`拖拽文件或文件夹到此处`

对应行为：

- `附加文件`：选择一个或多个外部文件，写入当前线程目录
- `附加文件夹`：选择一个外部文件夹，复制到当前线程目录
- 拖拽文件 / 文件夹：直接附加到当前线程目录

#### 工作区共享 tab 下的表现

- 标题：`附加到工作区`
- 说明：`这些文件或文件夹会进入工作区共享区，供后续线程复用`
- 拖拽文案：`拖拽文件或文件夹到此处`

对应行为：

- `附加文件`：选择一个或多个外部文件，写入工作区共享目录
- `附加文件夹`：选择一个外部文件夹，复制到工作区共享目录
- 拖拽文件 / 文件夹：直接附加到工作区共享目录

#### UI 原则

- 不再只显示“选择文件”一个动作
- 文件与文件夹分成两个显式按钮，避免用户猜测文件夹支持情况
- 标题和说明要始终带上目标范围，避免两个 tab 的入口看起来完全一样

### 二、列表区语义与来源表达

两个 tab 的主体都继续使用文件树，不做结构性重写。

列表中的项目来源可能有两类：

1. 用户从本地外部附加进来的文件 / 文件夹
2. Agent 在运行过程中生成的文件 / 文件夹

为了避免界面过重，只标识第一类：

- **外部附加**：显示轻量 badge `外部附加`
- **Agent 产出**：不显示来源标识，按普通文件或文件夹对待

这样可以满足两个目标：

- 让用户识别哪些资源是自己主动喂给系统的
- 不把列表变成满是来源解释的状态面板

### 三、外部附加路径追溯

对带有 `外部附加` badge 的项目：

- 鼠标 hover badge 时显示 tooltip
- tooltip 内容为该资源附加前的原始绝对路径

#### 说明

- 绝对路径只在 tooltip 中展示，不常驻在行内
- tooltip 不扩展更多解释文案，只显示路径本身
- 文件与文件夹统一采用这一规则

这条能力主要用于回答：

- 这个资源最初是从哪里附加进来的？
- 这个共享文件和我本地哪个目录对应？

### 四、两个 tab 的列表项动作

#### 当前线程文件

保留现有文件管理动作：

- 打开
- 在 Finder 中显示
- 重命名
- 移动
- 删除

这里不提供“附加到当前线程”动作，因为列表中的项目已经属于当前线程。

#### 工作区共享文件

保留现有文件管理动作：

- 打开
- 在 Finder 中显示
- 重命名
- 移动
- 删除

并新增一个复用动作：

- `附加到当前线程`

这个动作的目的，是把工作区共享资源快速引入当前线程，而不要求用户切换到另一个 tab 后再重新找入口。

### 五、空状态与文案

空状态文案需要从“文件系统视角”切到“上下文归属视角”。

#### 当前线程文件为空

建议文案：

- 主文案：`当前线程还没有文件或文件夹`
- 辅助文案：`可以在下方附加文件或文件夹，作为当前线程上下文`

#### 工作区共享文件为空

建议文案：

- 主文案：`工作区共享区还没有文件或文件夹`
- 辅助文案：`可以在下方附加文件或文件夹，供后续线程复用`

### 六、数据与元信息

为了支持 `外部附加` badge 与原始绝对路径 tooltip，需要为外部附加项目存一份附加元信息。

第一版建议元信息仅包含：

```ts
interface ExternalAttachmentMeta {
  absoluteSourcePath: string
  attachedAt: number
  attachedFrom: "thread" | "workspace"
}
```

#### 设计原则

- 只记录“外部附加”的项目
- 不为 Agent 运行产物补来源元信息
- 元信息不改变现有目录结构，只作为附加能力的旁路数据
- 文件和文件夹都可以挂载同一结构的元信息

#### 键设计

元信息应按“附加后在目标目录中的路径”索引，而不是按原路径索引。

例如：

- 线程：`<workspace>/<thread>/files/...`
- 工作区：`<workspace>/resources/...`

这样在列表渲染时可以直接根据当前条目路径查 badge 和 tooltip 信息。

### 七、关键交互流

#### 场景 1：给当前线程附加本地资料

1. 用户进入 `当前线程文件`
2. 在底部 `附加到当前线程` 区域：
   - 点击 `附加文件`
   - 或点击 `附加文件夹`
   - 或直接拖拽文件 / 文件夹
3. 资源进入线程文件树
4. 该资源显示 `外部附加` badge
5. hover badge 可看到原始绝对路径

#### 场景 2：沉淀共享资料

1. 用户进入 `工作区共享文件`
2. 在底部 `附加到工作区` 区域：
   - 点击 `附加文件`
   - 或点击 `附加文件夹`
   - 或直接拖拽文件 / 文件夹
3. 资源进入工作区共享树
4. 该资源显示 `外部附加` badge
5. hover badge 可看到原始绝对路径

#### 场景 3：把共享资源复用到当前线程

1. 用户进入 `工作区共享文件`
2. 在某个共享资源项上点击 `附加到当前线程`
3. 系统将该资源复制或链接到当前线程目录（实现细节由后续计划决定）
4. 线程 tab 中出现该资源

## 边界与待实现决策

以下点在本设计中已明确方向，但实现方式可在 planning 阶段确定：

1. `附加文件夹` 的系统选择器如何落地  
   桌面环境是否复用现有文件对话框能力，还是新增文件夹选择 IPC。

2. 工作区资源“附加到当前线程”采用复制还是引用  
   本设计只约束用户心智和入口，不在此阶段锁死底层复制模型。

3. 外部附加元信息的存储位置  
   可以是线程 / 工作区下的伴随元数据文件，也可以是统一索引存储，只要满足路径可追溯与重命名 / 移动后同步更新。

## 明确不做

- 不移除现有双 tab
- 不把线程文件与工作区文件合并成一个统一列表
- 不新增“Agent 产出”来源 badge
- 不在列表项常驻显示绝对路径
- 不增加批量选择、批量附加、批量提升能力
- 不把文件树替换成卡片式资源库

## 测试与验证建议

实现后至少需要覆盖以下验证：

1. 当前线程 tab 可附加文件
2. 当前线程 tab 可附加文件夹
3. 工作区 tab 可附加文件
4. 工作区 tab 可附加文件夹
5. 外部附加项目正确显示 `外部附加` badge
6. hover badge 能展示正确绝对路径
7. Agent 运行生成的项目不显示来源 badge
8. 工作区项目支持 `附加到当前线程`
9. 重命名 / 移动后来源元信息仍能正确对应
10. 删除项目后来源元信息同步清理
