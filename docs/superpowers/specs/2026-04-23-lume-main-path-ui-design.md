# Lume 主路径 UI 改版设计

**日期**: 2026-04-23  
**状态**: 已批准  
**范围**: `apps/web` 欢迎页、左侧栏、输入区第一批 UI 重构

## 概述

本次改版覆盖 Lume 的第一批主路径界面：

- 左侧栏
- 欢迎页主体
- 底部输入区

目标不是“尽量套用现有组件库”，而是**以设计稿为最高准则**，在保留真实数据驱动和现有核心交互能力的前提下，完成与设计稿一致的产品级界面重构。

本次采用的实施策略为：

- 设计优先，组件库服从设计稿
- 能复用的基础交互原语继续复用
- 强视觉区域使用 Lume 自定义品牌组件
- 浅色与暗色使用同一套结构，只切换主题 token

本次确认采用的视觉方向为：**精致还原型**。  
该方向优先恢复设计稿中的精细导航层级、中心舞台感、留白节奏和卡片阵列秩序。

## 目标

1. 让左侧栏在层级、精致度和节奏上接近正式设计稿，而不是继续维持当前偏“工具面板”的视觉语言。
2. 让欢迎页中部区域恢复设计稿中的中心舞台感，形成稳定的英雄区、筛选器、四卡主入口、三块信息面板结构。
3. 将输入区重构为品牌化 composer，保留现有输入能力但重做外观与状态语言。
4. 建立一套可持续扩展的 Lume 主题 token，使后续页面可以继续沿同一视觉系统扩展。

## 非目标

- 本次不重做设置页、技能市场、自动化页、普通会话页的完整 UI。
- 本次不改动后端数据模型，不新增新的业务实体。
- 本次不强制将所有现有页面都迁移到新视觉语言，只覆盖第一批主路径。
- 本次不以 shadcn 默认样式为目标，也不追求“尽量少写自定义组件”。

## 设计原则

### 1. 设计稿优先

如果 shadcn/ui 的现成组件形态无法满足设计稿，允许只复用其交互原语或完全自定义视觉层。

### 2. 数据结构不动，显示层可裁剪

工作区、线程、模型、最近会话、最近文件、推荐工作流仍由现有真实数据驱动，但显示层可以为了贴稿做如下调整：

- 固定槽位
- 条目截断
- 数量限制
- hover 才出现的次级操作
- 文案摘要长度压缩

### 3. 同结构双主题

浅色与暗色必须使用同一套布局、相同的视觉层级和一致的交互节奏，不允许出现 light/dark 两套不同的信息架构。

### 4. 品牌组件与基础原语分层

基础能力层可以来自现有组件体系，但品牌外观必须由 Lume 自己控制。

## 组件架构

本次主路径重构拆为三类品牌组件：

### `LumeSidebar`

负责左侧导航区的整体外观、间距、层级和状态表现。

内部承载：

- 顶部快捷操作区
- 工作区区块
- 线程树
- 底部收尾导航

### `LumeWelcomeSurface`

负责欢迎页主体的中心舞台布局。

内部承载：

- 品牌符号
- 主标题 / 副标题
- 工作区选择器
- 模型选择器
- 四张主功能卡
- 最近会话 / 推荐工作流 / 最近文件三块信息面板

### `LumeComposer`

负责底部输入区外观与交互状态呈现。

内部承载：

- TipTap 编辑器容器
- 附件入口
- `@文件 /Skill #MCP` 快捷入口
- 模型选择
- 思考级别选择
- 发送 / 停止状态按钮

## 可复用与自定义边界

### 继续复用的基础能力

- `Select`
- `Dialog`
- `Tooltip`
- `ScrollArea`
- TipTap 编辑器
- mention 建议列表机制
- workspace / thread / model / file 的现有数据来源与行为

### 不直接复用默认外观的区域

- 左侧栏整体外壳
- 欢迎页英雄区
- 主功能卡
- 三块信息面板的外观结构
- 输入区外层 composer 容器
- 导航激活态与品牌按钮外观

## 页面骨架

整体结构保持：

`TitleBar + Left Sidebar + Main Area`

但视觉分层调整为：

1. 顶部保留桌面标题栏可拖拽层，不承担主要视觉语言。
2. 左侧栏成为单独的轻量导航面板，边界更细，阴影更弱，强调层级秩序。
3. 主区域形成中心舞台布局，欢迎页中部保持明确的纵向节奏：
   - 品牌符号
   - 主标题 / 副标题
   - 工作区 / 模型筛选器
   - 四张主功能卡
   - 三块信息面板
   - 大型 composer

## 左侧栏设计

### 信息结构

左侧栏分为四段：

1. 顶部快捷入口
2. 工作区与线程树
3. 低优先级次级导航
4. 底部收尾入口

### 顶部快捷入口

固定展示：

- 新建聊天
- 搜索
- 技能
- 自动化（即将推出）

规则：

- `新建聊天` 为最高权重入口，采用品牌渐变主按钮
- `搜索` 为弱一级输入入口，采用轻边框搜索盒
- `技能` 与 `自动化` 为文本型导航项
- `自动化` 保留不可用状态和“即将推出”标记

### 工作区与线程树

继续使用现有工作区和线程数据，但视觉上改成设计稿中的轻树状导航。

保留：

- 工作区名称
- 工作区线程数
- 当前选中工作区
- 当前激活线程
- 按日期分组的线程列表

显示层规则：

- 组标题弱化，作为导航辅助，不作为强标题
- 当前激活线程使用淡色背景高亮条，不使用厚阴影卡片
- 非激活线程尽量仅保留文本与轻 hover
- 溢出标题积极截断
- 次级操作按钮尽量只在 hover 或激活态出现

### 底部区域

保留：

- 回收站
- 设置

规则：

- 作为低优先级区域收尾，不与主导航争抢视觉重心
- 视觉上更接近设计稿中的淡化工具入口

### 左侧栏明确调整点

相对于当前实现，本次会刻意去掉这些视觉特征：

- 厚玻璃卡片感
- 过强的阴影容器感
- 过重的 hover 背景块
- 工具感过强的分段盒子语言

## 欢迎页设计

### 英雄区

英雄区固定包含：

- 品牌符号
- 主标题：今天想一起完成什么？
- 副标题：在当前工作区中开始新的工作流

规则：

- 中轴对齐
- 保持较大上下留白
- 不因为数据多少改变英雄区结构

### 顶部筛选器

保留两个筛选器：

- 工作区
- 模型

规则：

- 继续使用现有真实状态
- 作为欢迎页的上下文控制器存在，不退化成普通表单控件堆叠
- 视觉上采用设计稿中的胶囊选择器风格

### 第一排四张主功能卡

该区域采用**固定四卡槽位**策略。

设计意图：

- 保持版式稳定
- 建立欢迎页“第一眼可操作入口”
- 强化设计稿中的产品舞台感

数据策略：

- 使用真实能力与真实跳转行为
- 卡片数量固定四张
- 当底层数据不足时，也优先保持槽位结构不塌陷

视觉要求：

- 四卡等宽等高
- 图标、标题、辅助文案、箭头动作统一层级
- hover 反馈轻，不出现厚重抬升感

### 第二排三块信息面板

固定承载：

- 最近会话
- 推荐工作流
- 最近文件

数据策略：

- 使用现有真实数据源
- 按设计稿控制条目数与摘要长度
- 目标不是“展示全部”，而是“展示最值得看的内容”

显示层裁剪规则：

- 最近会话展示最相关的 3 到 5 条
- 推荐工作流展示有限数量入口
- 最近文件展示有限数量条目和简化时间信息
- 摘要长度统一截断

### 欢迎页明确调整点

相对于当前实现，本次要恢复以下设计稿特征：

- 更明确的中心舞台感
- 更大的顶部留白
- 更稳定的四上三下卡片秩序
- 更克制的边框和更轻的悬浮感
- 更接近成品 UI 的信息层次，而不是开发态模块拼接感

## 输入区设计

### 功能保留

保留现有能力：

- 文本输入
- Enter 发送
- Shift + Enter 换行
- `@文件`
- `/Skill`
- `#MCP`
- 附件上传
- 模型选择
- 思考级别选择
- 发送中停止

### 结构重排

输入区改为设计稿中的大型 composer。

布局规则：

- 上层为输入内容区域
- 下层为左右分组工具栏
- 左侧放附件与快捷入口
- 右侧放模型、思考级别、发送按钮

### 状态设计

需要明确定义以下视觉状态：

- 空输入态
- 可发送态
- hover / focus 态
- 发送中态
- disabled 态
- 停止态

规则：

- 可发送态突出品牌按钮
- 空输入态弱化主按钮存在感
- 发送中与停止态视觉语言统一，不与旧页面混用

## 主题与 Token 策略

本次不继续停留在默认 shadcn 中性色，而是在语义层之上建立 Lume 品牌层。

### 语义层

保留并继续使用：

- `background`
- `foreground`
- `card`
- `primary`
- `secondary`
- `muted`
- `accent`
- `border`
- `input`
- `ring`

### Lume 品牌层

新增并统一到主题系统：

- `brand`
- `brand-2`
- `brand-foreground`
- `surface-1`
- `surface-2`
- `surface-3`
- `text-1`
- `text-2`
- `text-3`
- `border-strong`
- `glow-brand`
- `glow-soft`
- `shadow-panel`

### 使用规则

- 基础原语优先使用语义层 token
- 品牌组件优先使用 Lume 品牌层 token
- 所有浅色 / 暗色差异通过 token 切换完成
- 不允许页面里长期并存三套色彩系统：
  - 默认灰阶 token
  - 零散硬编码 `zinc/*`
  - 任意 `hsl(...)` 内联颜色

## 数据流与状态约束

### 保留的真实数据

- 当前工作区
- 工作区列表
- 线程列表
- 最近会话
- 最近文件
- 模型与 channel 选择
- 输入编辑状态

### 显示层允许做的处理

- 排序
- 截断
- 条目数限制
- 稳定槽位映射
- hover 才显示的操作

### 不允许做的处理

- 伪造业务数据替代真实数据
- 为了贴稿新增无来源的持久状态
- 让 light/dark 使用不同的信息架构

## 错误处理与边界情况

### 左侧栏

- 工作区为空时：保留结构骨架，但以空状态或低信息形式呈现
- 线程标题过长时：统一截断，不挤压整体节奏
- 线程操作不可用时：隐藏次级按钮，不保留空位

### 欢迎页

- 最近会话为空时：不破坏整体三栏节奏，使用空态文案或低干扰空态提示块
- 最近文件为空时：保持卡片结构稳定
- 工作区或模型未加载完成时：优先显示安全默认态，而不是让布局跳动

### 输入区

- 发送失败时：保留输入内容与上下文选择
- mention 查询失败时：静默失败，不破坏主输入流程
- disabled / sending 时：交互状态与视觉状态严格一致

## 测试与验证

### 视觉验证

- 浅色与暗色逐屏截图对照设计稿
- 左侧栏层级、留白、选中态与 hover 态对照
- 欢迎页四卡与三面板布局对照
- composer 的空态、输入态、发送态对照

### 行为验证

- 工作区切换仍然正确影响欢迎页上下文
- 模型选择仍然正确传递
- 最近会话点击仍然打开真实线程
- 输入区的发送、停止、附件、mentions 都保持可用

### 回归验证

- 左侧栏折叠 / 展开行为
- 欢迎页创建线程流程
- 输入区与普通会话页的共用能力不回归

## 分阶段实施建议

### Phase 1

- 收口主题 token
- 建立 `LumeSidebar` / `LumeWelcomeSurface` / `LumeComposer` 的外壳
- 完成欢迎页与左侧栏主视觉替换

### Phase 2

- 精修卡片内部排版
- 完成所有交互状态统一
- 对浅色与暗色做逐项视觉对齐

### Phase 3

- 将第一批视觉系统向后续页面扩展
- 评估哪些现有基础组件需要二次封装为通用 Lume 组件

## 实施约束

- 不新增依赖
- 优先复用现有业务数据与行为
- 小步可验证迁移
- 所有实现以设计稿一致性为最终验收标准
