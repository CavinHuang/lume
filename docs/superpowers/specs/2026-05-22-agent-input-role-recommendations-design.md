# Agent 输入区角色推荐设计

> 日期: 2026-05-22
> 状态: 已确认，进入实现
> 范围: 主 Agent 输入区的内置角色推荐与一键选人体验

## 背景

Agents 设置页已经把 Alice 风格的 11 个内置角色注册到 shared registry，并让 sidecar runtime 可以通过 `Agent` 工具使用这些角色。下一步要让用户在主输入区感知和使用这些角色，而不是只在设置里查看。

用户确认选择方案 A：在主 Agent 输入体验里增加任务推荐与一键选人。同时要求按用户体验和功能设计推进，不写桥接或包装代码。

## 目标

- 用户输入任务时，输入区下方展示最多 3 个推荐角色。
- 推荐来自现有 `suggestAgentRoles()`，不维护第二份规则。
- 点击角色后，直接把当前草稿改写成面向该角色的自然语言调度指令。
- 不改 runtime 协议，不新增桥接层，不新增 wrapper 组件。
- 逻辑保持可测试：推荐、展示文案、草稿改写放在小的纯函数中。

## 非目标

- 不自动启动 subagent。
- 不做多 Agent 并发编排。
- 不新增自定义 Agent 存储。
- 不改 `Agent` 工具协议。
- 不把推荐接进欢迎页，先聚焦主线程输入区。

## 用户体验

当输入区存在可识别任务时，在 composer 支持内容区域展示一行推荐 chip：

- 标题为短文本，如 `推荐角色`
- 每个 chip 显示中文名、职能和命中关键词数量
- 最多展示 3 个
- streaming、发送中、空输入时不展示

点击 chip 后：

1. 保留用户原始任务文本。
2. 在文本前插入稳定的自然语言指令：

```text
请使用 designer agent 处理这个任务：
<原任务>
```

3. 光标回到输入区，用户可以继续编辑或直接发送。

选择使用自然语言指令的原因：

- 符合当前主 Agent 的交互模型。
- 不需要新协议或桥接代码。
- 可被现有 runtime、prompt 和 `Agent` 工具自然消费。
- 后续升级为结构化团队编排时，可以替换点击行为，而不影响推荐函数。

## 实现边界

新增 `agent-input-role-recommendations.ts`，只负责：

- 从草稿生成推荐列表。
- 构造 chip 展示 label。
- 将角色选择应用到草稿文本。

`AgentInput.tsx` 只负责：

- 读取 editor text。
- 渲染推荐 chip。
- 点击后调用 editor 命令更新内容。

不新增通用 composer wrapper，不新增 desktop API，不新增 sidecar handler。

## 验证

需要测试：

- 空输入返回空推荐。
- 有命中任务时最多返回 3 个推荐。
- 推荐项包含角色、label、score、matchedKeywords。
- 应用角色选择会生成稳定的调度指令。
- 已经包含同一角色调度指令时不重复包一层。

组件视觉改动不做全量测试；只跑新增纯函数测试和 web typecheck。
