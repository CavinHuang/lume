# Goal

将 Lume 项目的架构分析转化为按优先级排列、可逐项验收的执行清单，先治理边界与稳定性，再推进能力与产品化。

## Steps

### P0：先建立可交付底座

1. **建立当前工程基线**
   - 动作：记录环境、依赖、typecheck、构建、web smoke、core smoke、MCP 和桌面链路现状。
   - 完成标准：每项都有命令、退出码、失败摘要和责任模块；形成可复现基线报告。

2. **锁定 Electron 与 sidecar 的生产启动链路**
   - 动作：验证 dev、build 产物、package 产物的资源路径、进程生命周期、崩溃、退出清理和日志。
   - 完成标准：三种模式都能启动并完成一次最小对话和工具调用；无孤儿进程；sidecar 失败不静默卡死。

3. **定义并落地统一权限与副作用确认边界**
   - 动作：统一 capability、风险级别、作用域、确认、审计规则。
   - 完成标准：高风险工具无法绕过 main/sidecar 检查；拒绝/取消/超时状态准确；外部副作用可审计。

4. **建立核心运行时最小回归测试集**
   - 动作：覆盖 Agent loop、工具调用、流式事件、断线、取消、超时、子代理生命周期和会话恢复。
   - 完成标准：正常、失败、取消、断线四类路径均可自动验证，且连续运行结果稳定。

### P1：收敛架构和平台治理

5. **收敛模块边界与依赖方向**
   - 完成标准：每个包有职责和允许依赖；协议单一来源；renderer/main/sidecar 越界依赖清零或有明确例外。

6. **统一事件、错误和任务状态模型**
   - 完成标准：跨边界事件有统一 envelope；错误有恢复分类；未知事件不会击穿消费者。

7. **完成 MCP、插件和工具注册治理**
   - 完成标准：工具显示来源/版本/风险/权限/状态；schema、重复名、超时、断开和禁用行为确定；远程 MCP 默认无本地高权限。

8. **补齐数据恢复、迁移与可观测性**
   - 完成标准：真源与索引可恢复；升级可迁移和回滚；日志脱敏；可追踪完整任务链路。

### P2：把差异化能力做成可靠闭环

9. **把记忆系统做成可控闭环**
   - 完成标准：记忆有来源和确认状态；冲突不静默覆盖；删除后不可召回；索引与 Markdown 真源一致。

10. **规范 Skill 与子代理编排协议**
    - 完成标准：选择可解释；报告带证据；结果必须验收；版本可追踪和回滚。

11. **收敛自动化与外部渠道的任务语义**
    - 完成标准：重试幂等；状态完整；重启不丢失或重复；发送失败不伪装成功。

### P3：稳定后再扩展体验与生态

12. **做跨平台打包与原生能力兼容矩阵**
    - 完成标准：支持平台均完成安装、启动、对话、工具、剪贴板、sidecar、Office 和原生能力探测；差异有明确提示。

13. **最后再做产品体验与生态扩展**
    - 完成标准：5 条核心端到端路径可完成成功/失败/取消闭环；高风险确认清晰；删除重复入口；新增能力不扩大未治理权限面。

## Risks & Assumptions

- 尚未执行 typecheck、build、smoke test 和跨平台验证，部分风险需要先建立基线。
- 工具、插件、MCP、自动化和 IM 具备外部副作用，必须先统一权限、确认与审计。
- 不做大规模重写，优先复用现有模式、删除重复代码、小步可回滚。
- Markdown 是记忆真源，向量索引是缓存；恢复、冲突、删除和迁移规则必须围绕这一点定义。
