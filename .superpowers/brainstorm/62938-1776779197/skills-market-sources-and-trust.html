Sources, Trust, and Install Flow

Phase 1 should feel simple for users, but internally model every listing as a source-backed package

Unified source model
Built-in Source
Ships with the app. Highest trust. Best default recommendations.
Local Source
Existing skills already present on disk. Importable into a workspace.
GitHub Source
User installs from repo URL. Review required before trust is granted.
Subscribed Market Source
Future: official/team/community catalogs, all treated as pluggable sources.
Trust levels
Trusted
Review Required
Blocked by Default
Ordinary users mostly see trusted results first. Third-party market sources stay blocked unless the user explicitly enables advanced source access.
Recommended install confirmation
Step 1

Source summary

Show where this skill comes from, who maintains it, and whether it is built-in, local, GitHub, or subscribed market content.

Step 2

Risk summary

Show scripts, file operations, external tools, and any network expectations in plain language before install.

Step 3

Install target

Let the user choose workspace scope, then install. For blocked sources, send them through a stricter enable flow first.

A. Soft trust

GitHub skills install with a warning sheet, but no global source gate.

B. Source gate

Third-party sources are disabled by default. User must explicitly enable advanced sources first.

C. Repo-only exception

GitHub install is allowed with review, but subscribed third-party markets stay blocked until enabled.

My recommendation
Use C for Phase 1. It supports the GitHub path you want without making generic third-party markets feel casually safe.
