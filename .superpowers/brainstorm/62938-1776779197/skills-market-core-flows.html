Core Pages and Key Flows

Phase 1 should optimize three everyday jobs: discover, install from GitHub, and manage what is already installed

1. Discover

User lands in Skills, browses trusted recommendations, filters by use case, and opens a detail view.

2. Install from GitHub

User pastes a repo URL, Lume validates it, shows a review sheet, then installs to a workspace.

3. Manage installed skills

User sees install state, workspace scope, update status, and can disable, remove, or inspect source.

Recommended page structure
Page A

Discover

Search, featured skills, trusted badges, categories, and source filters.

Page B

Skill Detail

What it does, example prompts, files preview, source identity, install CTA.

Page C

GitHub Install Sheet

Paste URL, fetch metadata, inspect risk summary, choose install target.

Page D

Installed

Enabled state, workspace bindings, source status, updates, remove actions.

Interaction principles

  • Discover and Installed are separate mental modes
  • Install from GitHub is a guided sheet, not a raw form
  • Risk language is plain, not technical jargon
  • Ordinary users always know what workspace they are installing into

What we avoid

  • No open publishing flow in Phase 1
  • No dense package-manager style table as the default view
  • No silent trust escalation for third-party sources
  • No mixing source subscription controls into the main browse flow
Recommendation
Keep Phase 1 to four concrete surfaces: Discover, Detail, GitHub Install Sheet, Installed. Everything else can be a sub-sheet or future iteration.
