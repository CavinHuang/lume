设计第三段：AI 分析引擎（Pattern Analyzer）

系统的"大脑"——从事件流中发现自动化机会

两种检测机制

分析引擎同时运行两种检测：结构化的频率统计 + AI 语义理解，互为补充。

分析引擎工作流程
① 频率检测器
结构化规则，实时统计
② 语义分析器
LLM 理解意图和痛点
▼ 汇聚 ▼
③ 建议生成器
合并检测结果，生成自动化建议

① 频率检测器（Frequency Detector）

不依赖 LLM，用结构化规则统计重复模式。轻量、快速、确定性高。

检测逻辑：
• 滑动窗口内（7天），统计相似事件序列出现次数
• 相似度判定：同 source + 同 type + payload 关键字段匹配
• 触发阈值：同一模式出现 ≥ 3 次，且跨越 ≥ 2 个不同日期
• 输出：{ pattern, count, firstSeen, lastSeen, samplePayloads }

示例：
用户连续 3 天在早上 9-10 点发送类似消息 "帮我总结 PR"
→ 频率检测器命中 → 输出重复模式

② 语义分析器（Semantic Analyzer）

利用 LLM 理解对话上下文，识别用户表达的痛点和隐含需求。

触发时机：
• Agent 对话结束时（消息流结束），对最近对话做一次分析
• 不是实时分析，避免频繁调用 LLM

分析内容：
• 用户是否表达了重复性工作的不满
• 用户是否在多次对话中请求类似任务
• 是否存在可以用定时/事件触发替代的手动操作

输出：
{ insight, suggestedAutomation, confidence, evidence }
confidence < 0.6 的建议直接丢弃，避免噪音

③ 建议生成器（Suggestion Generator）

合并两个检测器的结果，去重后生成最终建议。

Suggestion 接口：

interface AutomationSuggestion {
  id: string;
  workspaceId: string;
  title: string;              // "每天早上总结 GitHub PR"
  description: string;          // 面向用户的解释
  triggerType: 'cron' | 'event';   // 建议的触发类型
  triggerConfig: TriggerConfig;    // 触发配置
  actionPrompt: string;         // Agent 执行的 prompt
  evidence: string[];           // 为什么建议这个自动化
  source: 'frequency' | 'semantic' | 'both';
  confidence: number;          // 0-1
  status: 'pending' | 'accepted' | 'dismissed';
  createdAt: number;
}

节流与降噪策略

做

  • 频率检测器 5 分钟轮询一次（非实时）
  • 语义分析器每次对话结束最多分析一次
  • 同一工作区每天最多生成 3 条建议
  • 用户 dismiss 的模式 14 天内不再建议
  • confidence < 0.6 自动丢弃

不做

  • 不做实时分析（太重）
  • 不做跨工作区的模式检测
  • 不做用户画像/习惯学习
  • 不做复杂的 ML 模型训练
