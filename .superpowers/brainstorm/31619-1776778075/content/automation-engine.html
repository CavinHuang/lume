设计第四段：自动化引擎（Automation Engine）

建议展示 · 用户确认 · 任务调度 · 执行追踪

自动化任务的生命周期

生命周期状态机
建议
→ 用户确认 →
已创建
→ 启用 →
运行中
→ 暂停/完成 →
已停止
用户可随时 dismiss 建议 / 暂停任务 / 重新启用任务

触发类型：时间 + 事件 双模式

时间触发（Cron）
继承现有 cron 能力
• 标准 5 字段 cron 表达式
• 一次性定时执行
• 防并发执行（同任务不重叠）
事件触发（Event）
新增能力
• 匹配事件总线上的特定事件
• 支持条件过滤（如：特定文件变更）
• 支持 debounce（短时间内同类事件合并）

任务执行模型

执行流程：

1. 触发器匹配（cron 到时 / 事件命中）
2. 检查任务是否启用 + 未在运行中
3. 创建 Agent 线程（或复用已有线程）
4. 发送 actionPrompt 给 Agent
5. Agent 执行，可调用已授权的工具
6. 记录执行结果到 AutomationRun
7. 如果绑定了通知线程，推送结果摘要

AutomationRun 记录：
{ id, automationId, status: 'running'|'success'|'failed',
  triggeredBy: 'cron'|'event'|'manual',
  startedAt, completedAt, result, error }

权限与安全

原则：自动化任务的权限 ≤ 用户手动操作权限

• 建议确认时，同时确认该任务可以使用的工具列表
• 敏感操作（删除文件、发送消息到外部）需用户在确认时额外勾选授权
• 失败 3 次连续的任务自动暂停，等待用户检查
• 每次执行结果都记录，用户可随时审计

IPC 通道设计

// 自动化管理
automation:list-jobs
automation:create-job
automation:update-job
automation:delete-job
automation:list-runs
automation:run-now

// 建议管理（新增）
automation:list-suggestions
automation:accept-suggestion
automation:dismiss-suggestion

// 通知（后端 → 前端）
automation:suggestion-new   // 新建议产生
automation:run-completed  // 执行完成
automation:job-paused     // 任务被自动暂停 automation:run-completed  // 执行完成
automation:job-paused     // 任务被自动暂停
