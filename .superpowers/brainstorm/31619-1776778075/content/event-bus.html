设计第二段：事件总线（Event Bus）

系统的基础设施层——所有信号的统一入口

核心设计

事件总线是整个系统的脊梁。所有用户行为、Agent 对话、系统事件都汇入事件流，供下游的分析引擎消费。

事件总线内部结构
Event Emitter
各模块产生事件，写入总线
Event Router
按类型分类、路由到消费者
Event Store
持久化到 SQLite，支持回放
interface AutomationEvent {
  id: string;                 // 事件唯一 ID
  type: EventType;            // 事件类型
  source: EventSource;         // 信号来源
  workspaceId: string;        // 所属工作区
  timestamp: number;           // 时间戳
  payload: Record<string, unknown>;  // 事件数据
  fingerprint: string;           // 去重指纹
}

enum EventSource {
  agent_chat,      // Agent 对话消息
  tool_call,         // Agent 工具调用
  user_action,      // 用户界面操作
  file_change,      // 文件系统变更
  external_webhook,  // 外部服务回调
  system,           // 系统内部事件
}

事件类型设计

每种 EventSource 下定义具体的事件类型：

来源 事件类型 说明

存储策略

方案：SQLite 持久化

  • 事件写入 SQLite 表，按 workspace 分区
  • 保留 30 天滚动窗口，超期自动清理
  • 分析引擎查询时直接读数据库
  • 轻量、无需额外依赖（Tauri 自带）

不做的事

  • 不做事件回放/重放（YAGNI）
  • 不做分布式事件流（单机应用）
  • 不做精确一次投递保证

接入方式

各模块通过 EventBus 单例接入，提供 emit() 和 subscribe() 两个核心方法。遵循现有 AgentRuntimeStatusManager 的监听器模式。
